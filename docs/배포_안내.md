# Vercel + Render 무료 시연 배포

2026-10-31 기준. 기존 Railway 구성 대신 **Vercel 정적 React/Vite → `/api/*` rewrite → Render 무료 FastAPI 단일 프로세스 + 알림/AI 워커 스레드 + 컨테이너 내부 SQLite**를 사용한다. 영구 볼륨은 사용하지 않는다. SQL·DB 종류·migration·업무 규칙은 유지한다.

방문자는 프로그램 설치·환경변수·토큰 발급 없이 계정 버튼으로 접속한다. 이는 **시연용 계정 — 실제 인증 아님 · 가상 데이터**이며 공개 관리자 계정도 포함한다. 실제 민원·개인정보·음성을 입력하지 않는다. 모든 방문자가 같은 가상 DB를 공유하고 데이터가 초기화될 수 있다. 기관 운영에는 별도의 정상 인증이 필요하다.

## 1. Render Blueprint

1. Render 로그인 → New → Blueprint로 GitHub 저장소 `rladPsks/AXeL-AXEdu`를 연결한다. `render.yaml`이 포함된 커밋/브랜치를 선택한다. 작업 브랜치는 `codex/b-foundation`이다. 이전 PR #2는 과거 커밋까지만 병합되어 있으므로 최신 설정이 있는 브랜치를 확인한다.
2. 저장소 루트의 `render.yaml`을 사용한다. Blueprint의 `type: web`, `runtime: python`, **`plan: free`**를 확인한다. 루트 `requirements.txt`를 설치하며 시작 명령은 다음과 같다.

   ```sh
   uvicorn backend.main:create_app --factory --host 0.0.0.0 --port $PORT
   ```

3. Blueprint가 요구하는 `OPENAI_API_KEY`, `OPENAI_MODEL`을 Render에서 입력한다. 키는 서버 환경변수에만 둔다. 모델은 해당 프로젝트에서 사용할 수 있는 구조화 응답 지원 모델 ID로 지정한다. 키가 없으면 AI는 사용할 수 없지만 일반 업무·시연 로그인은 사용 가능하다.
4. 아래 환경변수를 확인하고 배포한다. 무료 시연에서는 디스크나 유료 DB를 추가하지 않는다.

   | 변수 | Render 값 |
   |---|---|
   | `PYTHON_VERSION` | `3.12.12` |
   | `SCHOOL_AGENT_DB` | `data/private/demo.sqlite3` |
   | `SCHOOL_AGENT_RUN_WORKER` | `1` |
   | `SCHOOL_AGENT_AUTO_SEED` | `1` |
   | `SCHOOL_AGENT_DEMO` | `1` |
   | `OPENAI_API_KEY` | 서버에만 입력, Blueprint `sync: false` |
   | `OPENAI_MODEL` | 서버에만 입력, Blueprint `sync: false` |

   `PORT`는 Render가 제공한다. 단일 프로세스로 실행하며 `--workers`/`--reload`를 추가하지 않는다. 기존 `WEB_CONCURRENCY`가 있으면 `1`로 맞추거나 제거한다. 별도 worker 서비스는 필요 없다.
5. `https://실제서비스.onrender.com/api/health`가 인증 없이 `{"status":"ok"}`를 반환하는지 확인한다. Render의 health check도 `/api/health`를 사용한다. 이 응답은 실제 모델 호출 성공을 보장하지 않는다.
6. `GET /api/demo/accounts`에서 토큰 없는 계정 목록을 확인한다. **시드 명령을 직접 실행할 필요가 없다.** API lifespan 시작 시 계정이 없는 DB에만 기존 seed 로직이 실행된다. 계정이 있으면 아무것도 덮어쓰지 않는다.

`sync: false` 비밀값은 기존 Blueprint 갱신 시 자동 반영되지 않을 수 있으므로 해당 서비스 Environment에서도 확인한다. `.env.example`은 예시이며 서버가 `.env`를 자동으로 로딩하지 않는다.

## 2. Vercel

1. 같은 GitHub 저장소와 최신 설정 브랜치를 연결한다.
2. **Root Directory `frontend`, Framework `Vite`, Build Command `npm run build`, Output Directory `dist`**를 지정한다. 설치는 커밋된 npm lockfile을 사용한다.
3. Vercel 프로젝트 Environment Variables에 **`VITE_SCHOOL_AGENT_DEMO=1`**을 추가한다. Production/사용할 Preview 환경에 적용하고 다시 빌드한다. 이 공개 플래그는 서버 준비 화면·계정 버튼을 켠다. 기본값은 꺼짐이므로 누락하면 기존 토큰 폼이 나온다. `frontend/.env.example`을 참고한다.
4. `frontend/vercel.json`의 `RENDER_BACKEND_URL`을 실제 Render 공개 호스트로 교체해 커밋한다.

   ```json
   {
     "rewrites": [
       { "source": "/api/:path*", "destination": "https://실제서비스.onrender.com/api/:path*" },
       { "source": "/(.*)", "destination": "/index.html" }
     ]
   }
   ```

   `RENDER_BACKEND_URL`은 환경변수 치환식이 아니라 직접 교체할 자리표시자다. `https://`와 `/api`를 중복 입력하지 않는다. API rewrite를 SPA fallback보다 먼저 유지한다.
5. 배포하고 `https://Vercel주소/api/health`도 JSON을 반환하는지 확인한다. 상대 API 경로는 그대로 사용하며 브라우저 요청은 같은 Vercel origin을 사용한다. OpenAI 키는 Vercel이나 `VITE_*`에 넣지 않는다.

## 3. 시연 흐름과 실패 처리

- Vercel 접속 → 준비 화면 → 계정 버튼 → **학교 관리자** 선택 → 가상 사건 조회 → 교사 업무 요청/지원 흐름을 확인한다.
- 시연 플래그가 켜진 프론트는 health JSON 성공까지 3초 간격, 개별 요청 최대 10초, 전체 약 2분 동안 재시도한다. Render의 HTML 로딩 화면이나 503 응답을 준비 완료로 취급하지 않는다. 제한 시간이 지나면 **다시 시도**를 누를 수 있다.
- 서버의 `/api/demo/accounts`가 404면 기존 토큰 입력 폼을 보여준다. 그 외 오류에는 재시도 안내를 제공한다.
- 교사 계정은 원래 사건 참여 규칙을 따른다. 처음에는 업무가 없을 수 있으므로 관리자로 업무를 요청한 뒤 교사로 전환한다. 다른 학교 관리자는 다른 학교 사건을 열 수 없다.
- 보호자는 별도 guardian 세션으로 로그인하고 연결 확인 화면을 사용한다. 초기 시드는 보호자를 사건에 자동 연결하지 않는다. 학교 관리자가 기존 보호자 연결 기능으로 확인한 뒤 보호자 계정에서 다시 확인한다. 보호자 대외 답변·접수 화면은 아직 A 모듈 연결이 필요하며 교직원 내부 화면을 대신 열어주지 않는다.
- 로그아웃/계정 전환 시 이전 API 요청을 취소하고 TanStack Query 캐시를 비운다. 토큰은 메모리에만 유지한다. 새로고침하면 계정 버튼에서 다시 로그인하며 `/cases/demo-case` 같은 주소의 새로고침이 404가 되지 않는지 확인한다.
- 서버 재시작으로 기존 토큰이 무효가 되면 계정 연결을 해제하고 버튼을 다시 누르면 된다. 새 토큰은 기존 발급 함수를 사용하며 8시간 후 만료된다.
- AI 요청이 별도 worker 없이 QUEUED → RUNNING → WAITING_REVIEW로 진행하는지 확인한다. OpenAI 실패가 업무·지원 요청을 막지 않는다. 공급자 호출은 종료 시 즉시 강제 취소되지 않으며 기존 lease·복구 규칙을 따른다.

## 4. 무료 시연의 데이터 수명과 업로드

Render 무료 서비스는 **15분간 외부 요청이 없으면 잠들고**, 다음 요청 시 보통 약 1분 동안 깨어난다. 휴면·재시작·재배포 시 컨테이너 파일 변경과 SQLite 데이터가 사라진다. 새 컨테이너에서는 자동 시드가 가상 데이터를 다시 만든다. 이는 이번 시연 구성의 의도된 동작이며 DB를 매 요청/매 시작마다 강제로 삭제하지 않는다. 심사·발표 직전에 Vercel 주소로 접속해 한 번 깨워둘 것을 권장한다.

앱 업로드 상한은 **10 MiB(10 × 1024 × 1024바이트)**다. 실제 유효한 파일로 작은 크기부터 상한까지 Vercel rewrite를 거쳐 업로드·다운로드를 확인한다. 413·타임아웃이 있으면 Render 직접 요청과 비교해 어느 구간에서 막히는지 확인한다. 앱의 한도와 Vercel Functions의 제한만으로 외부 rewrite 경유 성공을 단정하지 않는다. 첨부도 휴면 시 사라지며 저장 성공은 영구 보존을 의미하지 않는다.

## 5. 로컬 검증

기존 로컬/테스트 기본값은 모두 꺼짐이다. 시연 확인 시 서버에 세 플래그를 `1`, 프론트에 `VITE_SCHOOL_AGENT_DEMO=1`로 설정한다. 서버/프론트의 예시 env 파일만 복사해서는 자동 적용되지 않으므로 셸 또는 플랫폼 환경변수에 설정해야 한다.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
cd frontend
npm.cmd run build
npm.cmd test
```

실제 배포·OpenAI 호출·Vercel을 경유한 10 MiB 업로드는 별도 클라우드 검증이 필요하다. 로컬 브라우저 검증은 시연용 가상 DB와 공급자 없는 registry를 사용한다.

2026-10-31 검증 결과: 서버 81개·프론트 13개·기존 업무 브라우저 6개·새 시연 브라우저 4개 통과. 기본/시연 플래그 양쪽 production build 통과. 시연 브라우저는 HTML/503 뒤 재시도, 실제 가상 계정 로그인·전환, 보호자 분리, 404 토큰 폼 복귀, 새로고침 재연결, 2분 제한과 다시 시도를 확인했다. 단위 테스트는 자동 시드 재시작/동시 실행, 플래그 기본 비활성, 허용 목록/세션 namespace, 비활성·역할 변경 계정 거부, 내부 worker 시작·종료를 확인한다.

새 브라우저 검증의 재현 방법은 다음과 같다. 첫 명령의 디렉터리는 매번 새 이름을 사용한다.

```powershell
# 터미널 1: 가상 API, 8000 포트
.\.venv\Scripts\python.exe tools/e2e_demo_server.py .test-tmp/render-demo-new
# 터미널 2: 프론트 시연 플래그, 5174 포트
cd frontend
$env:VITE_SCHOOL_AGENT_DEMO='1'
npm.cmd run dev -- --port 5174
# 터미널 3: 브라우저 검증
cd frontend
npm.cmd exec -- playwright test --config playwright.demo.config.ts
```
