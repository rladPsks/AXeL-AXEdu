# 구성원 권한 설정 — 추가 구현 승인 범위

상태: 자동 승인 검토에서 처음 차단되었으나, 사용자가 아래 제한을 적용한 기능 개발을 명시적으로 승인했다. 승인 범위 안에서 API·화면과 가상 계정 테스트를 구현한다. 실제 계정의 권한을 지금 변경하는 승인은 아니다.

## 승인 요청 대상

같은 학교의 기존 구성원을 학교 관리자가 관리하는 `PUT /api/school/members/{user_id}` 기능과 해당 관리자 화면을 개발한다. 이 요청은 실제 계정의 역할을 지금 변경해 달라는 요청이 아니라, 제품에 해당 관리 기능을 추가하는 승인이다.

| 항목 | 제안 범위 |
|---|---|
| 호출자 | 현재 유효한 같은 학교 ADMIN |
| 대상 | 같은 학교의 이미 등록된 구성원. 신규 신원 생성·타 학교 변경 제외 |
| 변경 | ADMIN 또는 TEACHER 역할, 활성/비활성 상태 |
| 필수 입력 | expected_settings_version, role, active, reason |
| 동시 수정·중복 | 학교 설정 버전 검사, Idempotency-Key |
| 제한 | 자신의 권한 변경 차단. 다른 관리자에게 요청 |
| 책임 유지 | 사건 총괄·미완료 업무/지원·대기 인계·당번·현재/예정 부재·업무분장에 영향이 있으면 먼저 인계/해제하도록 차단 |
| 세션 | 변경 대상의 기존 세션은 폐기. 재활성화해도 이전 토큰을 복구하지 않음 |
| 이력 | 변경자·대상·역할/활성 상태·사유를 학교 감사 이력에 저장 |
| 개발 점검 | 가상 계정만으로 테스트. 실제 기관 인증은 별도 연동 |

사용자 승인 기록: “승인 — 제한을 적용해 기능 개발”. 권한을 부여하는 관리 기능이므로 위 대상·책임 검사·세션 폐기·감사 범위를 유지한다.

일정·부재 대체·업무분장·앱 알림·인계 처리는 별도로 계속 진행한다.
