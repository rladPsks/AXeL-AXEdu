# AXeL Demo Scenario

> 권장 시연 시간: 2~3분  
> 공개 배포: https://axel-axedu.vercel.app

## Demo Goal

시연의 목적은 화면 기능을 많이 보여주는 것이 아니라 다음 한 문장을 증명하는 것입니다.

> **민원이 담임에게 바로 전달되지 않고, AXeL이 먼저 근거·이력·업무분장을 확인해 학교 대응계획을 만든다.**

---

## Scenario 1 — 생활지도 불만

### Input

- 접수 경로: 유선전화
- 민원 종류: 생활지도 불만
- 관련자: 담임교사
- 발생 경위: 수업 중 생활지도 상황

민원 원문:

> 우리 아이가 수업 시간에 다른 학생보다 자주 지적받는다고 합니다. 어떤 상황 때문에 지도가 이루어졌는지 확인해 주세요. 담임선생님과 바로 통화하고 싶습니다.

### 보여줄 화면: 접수·AI 분류

다음 값을 순서대로 짚습니다.

1. **LLM 분류: LLM**
   - 실제 모델이 민원 의미를 구조화했다는 점
2. **RAG 공식 근거**
   - 학교민원 처리 매뉴얼 문서명·페이지·본문
3. **업무분장**
   - 1순위: 생활체육부장
   - 협조: 담임교사
   - 승인: 교감
4. **보호자 직접 연락**
   - 현재 단계에서는 요청하지 않음

### 발표 멘트 핵심

> “담임이 가장 많은 사실을 알고 있다는 이유로 민원 전체를 담임에게 넘기지 않습니다. Agent가 학교 업무분장을 먼저 확인하고, 담임에게는 수업 당시 확인 가능한 사실만 요청합니다.”

---

## Scenario 2 — 교직원 Fact Check

### 보여줄 화면: 교사 업무

생활체육부장/담임에게 생성된 사실확인 Task를 보여줍니다.

확인 포인트:
- 사건 총괄은 관리자에게 유지
- Task 수행자만 교직원으로 지정
- 질문은 민원 전체가 아니라 필요한 사실 중심
- callback은 Agent 계획과 관리자 판단에 따라 별도 관리

### 예시 회신

생활체육 담당:
> 10월 30일 수업 중 학생이 세 차례 자리에서 이탈해 해당 행동에 대한 생활지도가 이루어진 것으로 확인했습니다. 현재 확인된 범위에서는 특정 학생만 별도로 반복 지적한 사실은 확인되지 않았습니다.

담임:
> 당시 수업에서 학생의 자리 이탈 행동을 확인했고 해당 행동에 대해 지도했습니다. 다른 학생에게도 동일한 기준으로 지도하고 있으며 해당 학생만을 대상으로 별도 지도를 반복한 것은 아닙니다.

## Scenario 3 — Agent Re-planning

### 보여줄 화면: AI 지원 검토

필요한 Task가 완료된 뒤 AI 지원 검토 결과를 보여줍니다.

확인 포인트:
- 기록을 `FACT / CLAIM / UNVERIFIED`로 분리
- 추가 확인 필요사항
- 지원 방향
- 보호자 답변 초안
- 사용한 공식 evidence
- Validator 결과
- 자동 발송이 아니라 사람 검토 대기

### 발표 멘트 핵심

> “Agent는 접수 때 한 번 실행되고 끝나지 않습니다. 교직원의 사실확인이 들어오면 그 기록과 공식 근거를 다시 읽고 대응계획과 답변을 재구성합니다.”

## Optional — History Agent

같은 보호자/학생으로 유사한 민원을 다시 접수하면 과거 관련 사건을 찾습니다.

보여줄 수 있는 결과:
- `LINK_UNRESOLVED`: 이전 사건의 실질 답변이 끝나지 않음
- `REVIEW_FOLLOW_UP`: 새 사실/요구가 추가된 후속 후보
- `REVIEW_REPEAT`: 답변 완료 후 동일 요구 반복 후보

강조:

> “민원 횟수만으로 반복민원이라고 판단하지 않습니다.”

---

## Optional — Information Request

예시:

> 다음 주 현장체험학습을 신청하려고 합니다. 신청은 언제까지 해야 하고 어떤 절차로 제출하면 되나요?

예상:
- LLM 정보성 문의 분류
- 학사일정·교외체험 업무분장
- 공식 RAG 검색
- 학교별 실제 마감일 자료가 없으면 담당자 확인
- 담임에게 불필요하게 넘기지 않음

강조:

> “RAG에 답이 없으면 LLM이 학교별 날짜를 만들어내지 않고 담당자 확인으로 전환합니다.”

- [ ] RAG 근거 문서명/페이지/본문 표시
- [ ] 시연용 관리자/교직원 계정 접속 가능
- [ ] 데모 사건 1건을 미리 준비해 후반 Agent Review도 바로 보여줄 수 있게 함
- [ ] 실제 개인정보 사용 금지

## Failure-safe Demo

실시간 모델 호출이 지연되면:
1. 이미 생성해 둔 생활지도 사건의 접수·AI 분류 화면으로 이동
2. RAG / Duty / Teacher protection을 설명
3. 미리 완료한 Task가 있는 사건의 AI 지원 검토 화면으로 이동

즉 **시연의 핵심 증거 화면을 미리 한 건씩 준비**해 두는 것을 권장합니다.
