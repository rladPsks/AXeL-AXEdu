# 분야별 지원 추천과 출처 표시

- 초기 로그인 화면은 기존 대표 계정만 표시한다. ‘다른 시연 계정’ 선택 영역은 제거한다. 계정 자체와 권한 검증용 데이터는 보존한다.
- 접수 화면의 1·2·3순위는 분야 담당 → 사실확인 협조 → 검토·대체 지원 순서로 구성하고 같은 역할은 중복하지 않는다. 긴급·안전·교육활동 보호 사안은 학교장 지원 검토를 우선한다.
- 생활지도는 생활부장, 학사일정은 교무부장, 납부·환불은 행정 담당을 먼저 추천한다. 분야가 일치하지 않으면 민원대응팀에서 업무분장을 확인한다.
- 신규 사건 총괄은 추천 순서에 맞는 활성 관리자에서 선택한다. 사실확인 업무는 해당 분야의 실제 등록 담당자에게 연결한다. 분야 담당이 등록되지 않았으면 확인 가능한 학교 담당자에게 연결한다. 교감 고정 배정은 사용하지 않는다.
- 기존 사건의 총괄·업무 이력은 유지한다. 기존 접수 화면에도 현재 규칙의 추천 순위가 표시되며 실제 배정과 구분한다.
- 각 순위에 추천 이유, 업무분장 예시의 파일·항목·역할을 표시한다. 업무분장 예시는 해당 학교의 확정 자료가 아님을 명시한다.
- RAG 검색 자료에는 참고 이유, 문서명, 출처 ID, 발행기관, 조문·페이지·청크와 원문 URL 또는 업로드 파일명을 표시한다. 등록되지 않은 링크나 위치를 만들지 않는다.
- 공식 절차 참고자료와 학교 내부의 직위 추천 근거를 구분한다. RAG 자료가 특정 직위를 직접 지정한다고 설명하지 않는다.
- 신규 AI 지원 검토는 실제 검색·사용한 공식 자료의 출처를 서버에서 저장한다. 검색 결과에 없는 출처 ID를 모델이 인용하면 검토 결과 저장을 차단한다. 과거 결과에 상세 출처가 없으면 재실행 안내를 표시한다.

검증: 관련 Python 테스트 40개 통과, TypeScript·Vite 빌드 통과. 코드 변경은 배포 후 공개 시연 화면에 적용된다.
