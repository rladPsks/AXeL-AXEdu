## 판단

**미션의 방향과 교사·학교의 공동 처리 기반은 구현되어 있으나, L1~L3 전체가 하나의 완결된 사용자 흐름으로 구현됐다고 판단할 수 없다.** 접수·분류·업무·지원·인계·이력은 상당 부분 연결되어 있다. 그러나 대외 답변 확정·전달·종결, 반복 판단의 답변 상태, 지원 판단과 보고서, 번역 검토에 실제 연결 공백이 있다. 다른 사건의 원문이 이력 경로로 노출되는 권한 문제도 재현했다.

기준은 저장소 `docs/references/PRD_교사를_혼자_두지_않는_학교민원_에이전트.md`의 2장 미션·레벨 및 FR-01~FR-14다. 주최측 원본을 별도로 재수신·대조한 결과는 아니며, PRD가 추가한 상세 수용 기준과 주최측 레벨 항목을 구분해서 해석했다. 예를 들어 비한국어 2개 언어 시연은 PRD의 제안이다.

## 우선 수정할 결함과 재현

### 1. 다른 사건 원문이 이력으로 노출됨 — P1

`backend/features/intake.py:162`는 같은 학교·같은 보호자명/학생명의 과거 접수를 조회하지만, 요청자의 과거 사건 참여 권한은 제한하지 않는다. 그 결과를 `workflow.tools.history`에 원문과 함께 저장하고 현재 사건 접수 조회로 반환한다.

재현: 관리자가 비공개 가상 사건을 등록했다. 참여하지 않은 `outsider`의 해당 사건 직접 조회는 **403**이었다. 동일한 보호자명으로 새 사건을 등록한 뒤 자신의 접수를 조회하자, 과거 사건의 민감한 원문이 **200 응답 안에 포함**됐다.

수정 기준: 이력 검색과 입력 snapshot 생성 시마다 원래 사건·자료 권한을 확인한다. 후보 존재 여부와 원문 열람 권한을 구분하고 권한 없는 자료를 새로운 사건에 복제하지 않는다.

### 2. 답변 승인·전달과 종결이 단절됨 — P1

`backend/main.py:85`의 종결 guard는 기본값이 빈 목록이다. `backend/main.py:373`의 종결은 업무·학교 지원·인계만 검사하며, A의 답변·승인·전달 상태를 확인하는 기본 guard는 등록되어 있지 않다.

재현: 정보성 가상 접수 후 답변 생성·승인·전달 없이 `/api/cases/{id}/close`를 호출하자 **200, CLOSED**가 반환됐다. 업무는 0개, 등록된 종결 guard도 0개였다. 통합 `/api/*`에는 답변 승인·전달 전용 경로가 없다.

`backend/main.py:430` 이후의 구형 `/cases/.../deliver`는 별도 module-level FastAPI와 A 시연 DB의 호환 경로다. Render에서 실행하는 `backend.main:create_app --factory`의 B 사건 흐름과 같은 API·DB가 아니므로 통합 완료의 증거로 볼 수 없다. React도 전체 종결 연결이 아직 필요하다고 표시한다.

수정 기준: B 사건에 답변 초안·확정 버전·승인·전달 결과를 저장하고 종결 guard에서 이를 검사한다. 승인 후 수정은 재승인을 요구하고 전달 실패는 재시도 상태로 남겨야 한다.

### 3. AI 검토 완료를 실질 답변 완료로 계산 — P1

`backend/features/intake.py:165`는 `REVIEW_SUPPORT` 실행에 `reviewed_by`가 존재하면 `has_substantive_response`로 취급한다. 그러나 지원 검토 수락은 답변 발송이나 전달 확인과 다르며, 거절한 검토도 `reviewed_by`를 갖는다.

재현: 답변 본문이 빈 AI 지원 검토를 수락했고 대외 전달은 전혀 기록하지 않았다. 같은 내용으로 재접수하자 `unanswered_count=0`, `repeat_candidate=true`, `history_action=REVIEW_REPEAT`가 반환됐다. 기존 사건은 OPEN 상태였다.

수정 기준: 명시적인 실질 답변의 전달 완료 기록을 사용한다. 학교 미응답·약속 미이행·새 사실·답변 예정일과 함께 판단한다. 사람의 명시적인 미응답 정정 경로도 필요하다.

### 4. 긴급 분류가 관리자 업무·알림으로 이어지지 않음 — P1

`backend/features/intake.py:224` 이하의 실제 업무 생성은 `STAFF_OR_TEAM`에 한정된다. `ADMIN_REVIEW`는 제안 JSON과 총괄 지정으로 남고, 이 경로의 관리자 확인 업무·긴급 알림은 생성되지 않는다.

재현: 교사로 HIGH/SAFETY 가상 민원을 접수했다. 사건 총괄은 관리자였지만 생성된 `tasks`, `support_requests`, `inbox_notifications`는 모두 **0개**였다. 관리자가 목록에서 직접 발견할 가능성과 능동적인 즉시 확인 요청은 구분해야 한다.

수정 기준: 긴급 분류 시 지정 관리자·대체자에 확인 업무와 긴급 수신함 알림을 함께 생성한다. 일반 분류 승인 절차 때문에 즉시 도움을 지연시키지 않으며 처리·수신 확인을 남긴다.

### 5. 지원 판단과 보고서가 연결되지 않음 — P1

`backend/main.py:255`는 사건·접수·업무·지원 요청·감사 기록을 모아 `build_support_report`를 호출한다. 이미 구현된 `support_decisions`의 최신 판단 및 유효성 snapshot은 사용하지 않는다.

재현: 교육지원청 외부 지원 판단에 고유한 사유·대상·경로·학교의 후속 업무를 저장했다. 보고서 초안은 **200**으로 생성됐지만 판단 ID와 이 네 항목이 모두 빠졌다.

`agent/report_agent.py:6`은 JSON 초안을 생성한다. React에서 이 API를 호출하는 화면, 편집 가능한 보고서 저장·파일 내보내기 경로는 확인되지 않았다.

수정 기준: 최신 지원 판단 snapshot을 보고서 입력으로 사용하고 사건·판단 변경 시 오래된 보고서를 차단한다. 출처·첨부·후속 의무를 포함해 편집·미리보기·파일 내보내기로 연결한다. 실제 기관 전송 완료로 표시하지 않는다.

### 6. 학교 자료 기반 정보성 답변이 충분하지 않음 — P2

현재 `load_corpus()`의 검색 청크 35개 중 `school_policy`는 **0개**였다. `data/school_calendar.json`은 존재하지만 `backend/`, `agent/`, `frontend/src/`에서 일정 데이터 사용 경로는 확인되지 않았다. 체험학습 등교 시각 질문의 실제 검색 결과는 빈 목록이었다. 일정에 없는 시각을 만들지 않은 것은 올바르지만, 학교 자료를 연결한 답변 기능이 완성되었다는 증거는 아니다.

`agent/draft.py:14`의 최초 정보성 초안은 질문 내용과 근거 본문의 사실을 사용하지 않고 자료명·페이지 목록을 붙인다. 가상 근거에 `09:30`을 넣고 시각을 물어도 초안에는 `09:30`이 나오지 않았다. 후속 AI 검토는 답변을 생성할 수 있지만 최초 정보성 경로와 승인·전달까지 연결되어 있지 않다.

수정 기준: 학교별 검수된 규정·공지·일정을 검색 가능하게 하고, 질문에 대한 실제 답과 출처를 의미 단위로 연결한다. 정보가 없으면 관련 담당자에게 확인 업무를 만든다.

## 기능 간 추가 연결 공백

- **반복 기준:** A 자동 이력은 같은 이름·학생명과 최신 5건을 사용한다. B의 학교 설정과 불투명 비교 키는 별도 프로필을 사람이 입력해야 하며, 새 접수 후 조회한 B 비교 프로필은 `null`, 후보 0개였다. A와 B가 같은 사건을 다른 기준으로 해석할 수 있다.
- **답변 지연:** 시간 기준 저장·사람이 기록한 답변의 지연 표시가 있으나, 접수 확인과 실질 답변을 연계한 지연 알림 스캐너는 확인되지 않았다. 운영 설정 저장과 실제 알림 실행은 별개다.
- **다국어:** 원문·내부 번역·최종 답변을 대조하고 수정·확정하는 화면과 버전 API가 없다. AI 지원 검토의 공식 근거 재검색은 한국어 번역문 대신 원문을 사용한다.
- **사람의 수정·확정:** 접수 분류 화면은 조회 중심이다. 분류·대응계획을 수정하고 이유·확정자를 남기는 전체 경로가 없다. AI 지원 결과의 수락은 개별 답변 버전의 승인과 구분해야 한다.
- **통합 회귀 테스트:** 기존 E2E는 B 기반 흐름을 잘 검사한다. 새 접수→분류 확인→교사 회신→답변 승인·전달→재문의 비교→학교 지원 판단→보고서 내보내기→종결의 한 사건 전체 테스트는 없다. 전체 pytest 통과로 이 공백을 보장할 수 없다.

## 권장 완료 순서

1. 이력 권한 우회와 실질 답변 상태 오류를 수정하고 실패 재현을 회귀 테스트로 고정한다.
2. 긴급 관리자 알림·확인 업무를 연결한다.
3. B 사건의 답변 수정·승인·전달·종결 조건을 완성한다.
4. 학교 규정·일정 검색과 실제 정보성 답변을 연결한다.
5. B의 반복 기준·답변 지연 기록을 접수 자동 이력과 통합한다.
6. 관리자 지원 판단→보고서 편집·미리보기·내보내기를 완성한다.
7. 번역 대조·정정·확정 및 대시보드의 단계별 대기 지표를 보완한다.
8. 실제 가상 음성·다국어 입력·실제 AI 공급자로 검증한 뒤 L1→L2→L3 전체 시연을 한 사건 데이터로 수행한다.

현재 결과물은 교사를 단독 대응자로 만들지 않으려는 설계, 권한·사건 버전·학교 지원·인계·감사·동의 녹취 기반이 강점이다. 발표에서 입증 가능한 범위는 그 구현과 검증 결과이며, L1~L3 전체 완료나 기관 전송·실모델 품질까지 검증됐다고 표현하기에는 남은 작업이 있다.
